Three cooperating files form the client-side domain layer with a strict one-way dependency: `lib/types.ts` is the single source of truth for domain shapes (`ICategory`, `IMenuItem`, `IPromo`, `IOrder`, `ICoupon`, `ISettings`, etc.) and is deliberately framework-agnostic so it can be imported from both server and client components. `lib/staticData.ts` provides frozen fallback datasets (`STATIC_CATEGORIES`, `STATIC_MENU_ITEMS`, `STATIC_PROMOS`, `STATIC_SETTINGS`) typed against those interfaces; its header explicitly forbids importing server-only modules (mongoose/jwt) to keep it safe for client-side consumption. `lib/store.ts` depends only on `types.ts` (via `import type`) and implements runtime state: it defines `CartItem` and `TableSession` (extending types from `types.ts`), persists them under `selera_sambal_*` keys in `localStorage`, and exposes pure functions (`getCartItems`, `addToCart`, `updateCartQty`, `removeCartItem`, `clearCart`, `getTableSession`, `saveTableSession`, `getManualTableNumber`, `saveManualTableNumber`, plus order-history helpers). Reactivity is decoupled via two lightweight pub/sub classes — `StoreEvents` (no-arg listeners) and `SearchEvents` (typed `(q: string) => void` listeners with current-query echo) — instantiated as module-level exports (`storeEvents`, `searchEvents`). Mutating store functions call `storeEvents.notify()` after persisting, letting consumers subscribe once and react to any cart/session change. All browser-accessing functions guard with `typeof window === 'undefined'` to support Next.js SSR.
